Hypothesis: a small explicit change frame plus a frozen reference can catch unrequested compatibility changes with less semantic invention than doc-only test generation. Differential testing is established prior art (CrossHair diffbehavior: https://crosshair.readthedocs.io/en/latest/diff_behavior.html). No algorithmic novelty is claimed. Use stdlib exhaustive finite enumeration for this448-input domain; do not build a solver or new orchestrator.

Implementation scope: pure framework/preservation.py validates a caller-pinned policy, exact finite trace coverage and type-sensitive outputs, then compares only inputs outside the declared allowed-change box. Separate worker probes import actual DRF modules; the host comparator owns scope/reference and runs outside candidate code. A matching preservation guard is not verification of the changed region or whole-task completion. The reference may already contain bugs. Policies are experimental proposals until independently approved.

Proposed domain: two public permission classes, authenticated boolean, seven methods and16 backend permission combinations (448 inputs). Allow changes only for authenticated GET/HEAD across the class family (64 inputs); require reference behavior on the remaining384. This is a retrospective proposed scope selected with historical knowledge, not a production contract or blind discovery. In particular, reference behavior permits anonymous writes when an explicit backend grants them; do not silently invent a stricter requirement. Both methods and backend assumptions require owner review before using this as authoritative acceptance.
