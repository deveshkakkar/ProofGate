## Repair the output contract before another author trial

The unified-diff response format was a poor choice for these short, tool-disabled sessions: it made valid patch encoding a prerequisite before any business behavior could be evaluated. This was an output-contract failure in this experiment, not a successful comparison of application repairs.

A separately prepared, unexecuted replacement uses `module-edit-schema.json` and the pure `module_edits.apply_edits` function. The caller supplies a trusted original-source SHA256 independently. The author echoes it and returns at most8 exact old/new text replacements for the fixed report module. Every old substring must occur exactly once in the original; edits must be disjoint and are applied simultaneously. Wrong source/pins, ambiguous/missing/overlapping text, no-ops, paths/extra fields, invalid types and oversized input/output reject. The function returns text without writing files or executing source. Syntax and application correctness remain separate checks.

This replacement cannot convert either recorded raw diff into a scored result. Its tests use synthetic text fixtures; there has been no live-provider validation of the new schema and no new application run.
